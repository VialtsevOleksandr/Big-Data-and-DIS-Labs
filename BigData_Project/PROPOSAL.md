# Заявка: мовний перехід рецензентів Steam

**Питання до даних:** скільки рецензентів Steam перейшли з російської мови відгуків на українську, коли це сталося і чи надовго.

## 1. Датасет

|---|---|
| Назва | Steam Reviews, Games and Tags |
| Посилання | https://www.kaggle.com/datasets/sergiodelcarpio/steam-reviews |
| Джерело | публічний Steam Web API, зібрано відкритим конвеєром https://github.com/sadelcarpio/steam-recsys-e2e |
| Знімок | 2026-10-30, відгуки з 2010 року |
| Записів (відгуків) | 121 312 346 |
| Ігор | 184 885 |
| Формат | Parquet (zstd), 13 файлів `reviews-000.parquet` … `reviews-012.parquet` по 10 000 000 рядків |
| Розмір файлів, МіБ | 22 522,701 |
| Розмір без стиснення, МіБ | 37 693,103 |
| Ліцензія | формальної немає; за описом автора дані зібрано «for research and education» |

## 2. Схема таблиці відгуків

| Колонка | Тип | Що зберігає | Використовую |
|---|---|---|---|
| `user_id` | int64 | псевдонім автора (незворотний хеш SteamID, стабільний для одного користувача) | так |
| `language` | string | мова відгуку, яку віддає Steam (31 значення: `english`, `russian`, `ukrainian` …) | так |
| `reviewed_at` | timestamp | час публікації відгуку, UTC | так |
| `review` | string | текст відгуку | лише у 2 файлах, для перевірки поля мови |
| інші 17 колонок | int64, double, bool | `review_id`, `game_id`, `is_positive`, `updated_at`, час гри, кількість ігор і відгуків автора, голоси, ознаки покупки | ні |

## 3. Задача

Для кожного користувача відновлюю історію мов його відгуків у часі та присвоюю йому один тип автора. Над цими типами рахую три результати:

1. Кількість стійких переходів за місяцями (головний результат).
2. Чи перехід надовго: частка стійких переходів і тих, хто не закріпився, за місяцем першого українського відгуку.
3. Хто дав зростання української: кількість українських відгуків за роками за типом автора.

Одним проходом відповідь не отримати: тип автора є властивістю всієї його історії, а не окремого відгуку. Спершу треба згорнути відгуки до історії користувача, і лише над цим агрегатом можна рахувати динаміку за місяцями та роками.

### Що вважаю переходом

Датою переходу вважаю перший відгук українською. Один український відгук серед російських може бути випадковістю або помилкою в полі мови, тому перехід має підтверджуватися кількома відгуками з обох боків.

Позначення для одного автора:

- **Р-до** — кількість російських відгуків до дати переходу;
- **У** — кількість українських відгуків від дати переходу;
- **Р-після** — кількість російських відгуків після дати переходу;
- **N** — поріг, тобто скільки відгуків потрібно з кожного боку.

Кожен автор, який має хоча б один український відгук, отримує рівно один тип:

| Тип автора | Умова |
|---|---|
| Стійкий перехід | Р-до ≥ N, У ≥ N і У > Р-після |
| Не закріпився | Р-до ≥ 1 і Р-після ≥ У |
| Без російської | Р-до = 0 |
| Замало даних | Р-до ≥ 1 і У > Р-після, але відгуків менше, ніж вимагає поріг N |

Поріг N:

| N | Що означає | Роль |
|---|---|---|
| 1 | 1 російський до, 1 український після | м'який: людей найбільше, але багато шуму |
| 2 | 2 до, 2 після | основний: на ньому рахую всі три результати |
| 3 | 3 до, 3 після | суворий: людей мало, сумнівів найменше |

Результат 1 рахую для всіх трьох значень N. Кількість переходів зі зростанням N падатиме; перевіряю, чи пік припадає на ті самі місяці. Якщо так, висновок не залежить від вибору порога.

Приклад: автор написав 1 відгук російською, потім 1 українською. При N = 1 це стійкий перехід, при N = 2 і N = 3 — замало даних.

### Обмеження

- Поле `language` показує заявлену мову (її обирає автор, за замовчуванням це мова клієнта Steam), а не мову тексту. Точність поля окремо перевіряю текстом на 2 повних файлах.
- Автори, які перейшли незадовго до знімка, ще не встигли ні закріпитися, ні повернутися, тому останні місяці оцінюються гірше.

## 4. Чернетка етапів

| Етап | Ключ | Що рахую | Shuffle |
|---|---|---|---|
| 0. Чистка | — | відкидаю рядки без користувача, мови чи дати та з датою поза діапазоном 2010–2026; мову зводжу до трьох груп: російська, українська, інша | немає |
| 1. Місячний профіль | (`user_id`, група мови, місяць) | кількість відгуків | 1 |
| 2. Історія користувача | `user_id` | з результату етапу 1: дата переходу і тип автора для N = 1, 2, 3 | 2 |
| 3. Підсумки | (місяць переходу, тип автора); (рік, тип автора) | три результати з розділу 3 | 3 |

Етап 2 працює лише над агрегатом етапу 1, етап 3 — лише над результатом етапу 2.

Перевірка поля мови (окремий крок на 2 повних файлах): для відгуків із `language` = `russian` або `ukrainian` порівнюю поле з текстом за літерами. `і ї є ґ` є лише в українській, `ы э ъ ё` — лише в російській. Результат: частка розбіжностей і частка коротких відгуків, де мову визначити не можна.

## 5. Які дані завантажую

Parquet зберігає колонки окремо, а сервер Kaggle віддає довільні частини файлу, тому завантажую лише потрібне.

| Що | Рядків | Розмір, МіБ |
|---|---|---|
| 3 колонки з усіх 13 файлів (`user_id`, `language`, `reviewed_at`) | 121 312 346 | 2 248,040 |
| 2 повні файли з текстом (`reviews-000`, `reviews-006`) | 20 000 000 | 3 742,893 |
| **Разом** | | **5 990,933** |

Ті самі 3 колонки без стиснення займають 2 369,916 МіБ.
