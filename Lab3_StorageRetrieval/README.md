# PostgreSQL і DuckDB — зберігання та аналітичні запити

Практичне завдання 3 з розподілених інформаційних систем. Однакові продажі завантажуються в рядкову PostgreSQL і стовпчикову DuckDB; для дев’яти запитів вимірюються медіани після прогріву.

Набір: seed `20050406`, 100 магазинів, 2 000 товарів, 115 типів, 3 000 000 чеків і 29 990 001 позиція за 2025 рік. Для запитів 7–9 рахуються різні типи товарів у чеку, незалежно від кількості та повторення типу в різних позиціях.

## Встановлення і запуск

Потрібні локальний PostgreSQL 18 та Python 3.13. DuckDB встановлюється як Python-бібліотека. На Windows із папки цієї лабораторної:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

У `.env` вкажіть власні параметри PostgreSQL і пароль. Користувач має мати право створювати базу `storage_retrieval_lab`, або ця порожня база має вже існувати й бути доступною для створення таблиць.

```powershell
python load_data.py --generate
python benchmark.py
python index_experiment.py
```

Перша команда створює CSV та маніфест у `data/source`, перевіряє їх і завантажує в PostgreSQL та `data/sales.duckdb`. Наявні таблиці й набори автоматично не перезаписуються. Якщо CSV вже готові, для імпорту достатньо `python load_data.py`.

Заміри: один прогрів і п’ять повторів на запит, ліміт виконання 600 секунд, час включає `execute + fetchall`. Кеші не очищуються. PostgreSQL і DuckDB виконуються послідовно. Не запускайте інші важкі запити під час вимірювань. При відкритому DuckDB UI закрийте Python-процес, що утримує файл бази.

Експеримент повторює запити 3–5 з індексом `idx_receipt_items_product_receipt_cover` і без нього. Індекс тимчасово видаляється всередині транзакції, яка завершується `ROLLBACK`: початковий індекс відновлюється, дані не змінюються. Поки триває ця фаза, інші звернення до таблиці позицій можуть очікувати завершення транзакції.

## Файли для перевірки

- `salesgen/`, `configs/full.json` — генератор та параметри відтворення.
- `load_data.py`, `connections.py` — створення схем і завантаження тих самих CSV в обидві бази.
- `queries.sql` — однакові дев’ять SQL-запитів для обох баз.
- `results/schema-postgresql.sql`, `results/schema-duckdb.sql` — фактичні DDL-команди завантажувача.
- `results/benchmark.csv` — медіани; `benchmark.json` — повтори, SQL, результати, плани та умови запуску.
- `results/index-experiment.csv`, `results/index-experiment.json` — експеримент з індексом.
- `results/er-model.png`, `results/er-model.svg` — ER-діаграма.
- `results/observations.json` — час генерації/імпорту та окремо позначені приблизні ручні спостереження.
- `results/hardware.json` — конфігурація ноутбука, на якому отримані результати.

Фактичні CSV, файли баз, `.env`, середовище Python і тимчасові результати виключені з Git. Звіт подається окремо.
